# 管理员用户管理

管理员登录后，从左侧“用户管理”进入。普通用户和维修人员无法访问用户目录或对应接口。

## 支持的操作

- 按姓名、账号、邮箱、学号/工号或班级搜索，按角色和启用状态筛选，每页20人。
- 新建普通用户、维修人员或管理员账号。设置初始密码；学生填写学号和班级，维修人员填写专长。普通学生和教师也可走邮箱验证注册流程。
- 修改姓名、校园资料、角色、宿舍房间及维修专长。宿舍选择来自已有台账，普通用户只能访问其获授权的私人宿舍。维修人员和管理员按角色访问，因此清除其个人宿舍字段。
- 停用或恢复账号。停用后禁止登录、撤销会话和未使用验证码，保留历史工单与操作主体。使用停用代替物理删除，避免维修记录失去关联人员。
- 核实身份后重置密码，原密码、会话和已有找回验证码失效。密码仅以随机盐加 PBKDF2 哈希保存，不在目录或审计记录返回。
- 查看最近50条管理记录，含操作者、时间、修改前后字段和操作说明。

## 业务约束

1. 管理员不能停用自己或撤销自己的管理员角色，系统必须保留至少一个启用的管理员。
2. 维修人员存在未完成工单时，不允许停用或转为其他角色；先在工单中心移交或完成验收。
3. 已停用维修人员不进入派单列表，接口也拒绝派单。
4. 修改资料或权限后，目标用户需要重新登录。修改自己的资料或密码也会退出当前登录。
5. 保存使用版本号校验；另一个管理员先修改后，旧页面提交会收到冲突提示，需重新打开。
6. 邮箱和邮箱验证状态只读，不能以管理员编辑绕过验证。管理员新建账号不绑定邮箱，初始密码需私下交给本人；该类账号未绑定验证邮箱时，通过管理员核实身份后重置密码。

## 数据库及接口

`users` 新增 `enabled`、`version`、`updated_at`；历史账号默认启用。`user_events` 保存账号管理审计，不包含密码、盐、验证码或登录会话。

| 方法 | 接口 | 功能 |
|---|---|---|
| GET | `/api/users?q=&role=&enabled=&page=` | 分页目录、统计及可选宿舍 |
| GET | `/api/users/{id}` | 用户资料、未完成任务数、最近管理记录 |
| POST | `/api/users` | 创建账号 |
| POST | `/api/users/{id}` | 更新用户，携带 version |
| POST | `/api/users/{id}/password` | 重置密码，携带 version |

所有写操作验证管理员权限与 CSRF。账号变更在 SQLite 事务内完成，审计与资料更新一并提交。

测试：`python -B -m unittest -v test_users`。`test_users_browser.mjs` 使用临时数据库、独立 Chrome 会话验收完整页面，不修改主演示数据。
