# 设计说明

本文说明 Module 1 与 Module 2 的技术选型、算法参数与验证方式，可作为最终报告
实现章节的素材。

## 1. 范围与边界

| 模块 | 包含 | 不包含 |
|---|---|---|
| Module 1 | 制度问答、引用溯源、拒答、知识缺口统计、语料维护 | 开放式闲聊、个人成绩查询、语音输入 |
| Module 2 | 四项指标评分、等级判定、自动预警、教师留言 | 成绩预测、自动处分、考勤监控 |

两个模块共享 `users`、会话与基于身份的角色控制，不与 Module 3 至 Module 6 耦合。
合并到主系统时只涉及三处改动，见 `INTEGRATION.md`。

## 2. 架构

```
浏览器（原生 JavaScript，视图函数返回 HTML 字符串）
   |  fetch /api/*  +  X-CSRF-Token
   v
app.py             路由分发、会话、静态资源、后台巡检线程
   |-- core/http.py          Router、Ctx、APIError（模块与框架解耦的契约）
   |-- core/auth.py          登录、Cookie 会话、CSRF、身份判断
   |-- core/db.py            SQLite 建表、演示账号、合成学业数据
   |-- modules/learning_qa.py    Module 1
   `-- modules/risk_warning.py   Module 2
```

技术约束：主系统为纯标准库单体应用，因此本子系统不引入 FastAPI、React 或构建
工具。收益有三点：课堂环境无需联网安装依赖；合并时不需要适配第二套框架的生命周期
与鉴权中间件；代码量小，评审可直接阅读业务逻辑。

模块通过 `routes()` 暴露 `(method, pattern, handler)` 三元组，`handler(ctx)` 只依赖
`ctx.conn`、`ctx.user`、`ctx.body`、`ctx.query` 与 `ctx.params`。该契约使模块迁移
等同于注册若干条路由。

## 3. Module 1：检索增强问答

### 3.1 技术选型

课程原型不存在问答标注数据，无法训练或微调模型；制度类问题要求答案可核查，
自由生成的风险不可接受。检索增强方式将事实来源交给检索，将表述交给模型，
检索结果本身可作为证据展示。

### 3.2 语料与分块

- 7 份 Markdown 文档，元数据包含 `doc`、`title`、`owner`、`version`、`updated`，
  引用时可显示责任部门、版本与更新时间。
- 按 `##` 章节切分，章节内按段落拼接到 160 至 480 字，超长段落按句号断开。
- 段落是引用单位，一个段落只属于一个章节，引用 `[1]` 指向确定章节。

### 3.3 检索参数

| 参数 | 取值 | 依据 |
|---|---|---|
| k1 | 1.4 | 段落长度 100 至 500 字，采用常规默认值 |
| b | 0.65 | 段落长度差异有限，长度归一化不需取满 |
| 标题权重 | 3 | 提到“奖学金”时应提升整篇文档，而非仅正文词频高的段落 |
| 章节权重 | 2 | 章节名通常是问题的直接答案所在 |
| 单字权重 | 0.38 | 中文单字区分度低，仅用于兜底召回 |
| 同义词权重 | 0.45 | 口语映射用于补充召回，不应覆盖原词 |

系统不引入分词库，中文采用二元字切分：`作业延期提交` 切为
`作业/业延/延期/期提/提交`。制度文本词形稳定，二元字召回率满足需要，且不依赖词典。

检索示例（问题：作业晚交几天会扣多少分？）：

```
18.28  考核与成绩评定办法 · 3. 作业延期提交
 4.92  考核与成绩评定办法 · 6. 学术不端
```

### 3.4 重排规则

同一文档内两个段落分数差小于 5% 时，优先呈现章节序号较小者。问题“我想申请奖学金”
同时命中「2. 申请时间与材料」（15.23）与「7. 违规处理」（15.48），后者词频略高，
但不宜作为首个答案。分数差大于等于 5% 时不干预，例如“挂科了怎么办”命中的
「补考与重修」分数明显更高。

### 3.5 回答路径

```
检索前 6 段
   |-- 最高分 < 4.0  -> 拒答（列出最接近的章节）
   `-- 其他
        |-- 已配置 Ollama -> 生成：以检索结果为唯一输入，要求逐句标注 [n]
        |                     模型失败或输出 INSUFFICIENT -> 退回抽取式
        `-- 未配置        -> 抽取：按词项重叠选取原文句子，拼接后标注 [n]
```

引用编号一致性由测试保证：

- 抽取式：编号按引用块在本次回答中的出现顺序编排，`citations[i].n == i + 1`；
- 生成式：模型输出的 `[n]` 指向输入上下文的序号，系统按该序号反查检索结果并重新
  编号，越界序号丢弃；
- 模型未标注出处时，系统补充来源并注明由系统补充，不假定模型已标注。

### 3.6 多文件引用与追问建议

制度问题常常横跨多份文件。例如"期末挂科了怎么办，会不会被学业预警"同时涉及
《考核与成绩评定办法》与《学业进度与学业预警管理办法》。抽取式路径的处理方式：

1. 以最高分段落所属文件为第一来源；
2. 按文件分组，取每份文件在检索结果中的最高段落；
3. 仅当该段落分数不低于首段分数的 50% 时纳入，最多纳入三份不同文件；
4. 同一文件的次要段落不重复引用——它们已经出现在"检索结果"列表中，点开即可查看。

这样单文件即可回答的问题（如"图书馆一次能借几本书"）仍只给一个来源，避免把整篇
文档塞进答案；跨文件问题则给出 2 至 3 个来源。

每条回答还附 2 至 3 条追问建议，取自"检索命中但本次未引用"的章节，句式统一为
"〈章节名〉是怎么规定的？"。点击后按普通提问处理，不需要额外的多轮上下文状态。

### 3.7 原文查看与 Word 导出

`GET /api/qa/source/<doc_id>` 返回文档元数据与 Markdown 原文，供前端弹窗展示；
加 `?format=docx` 时由 `modules/docx_export.py` 转成 Word 附件下载。

导出不使用第三方库：`docx_export` 手写最小 OOXML（`[Content_Types].xml`、`_rels/.rels`、
`word/document.xml`），用标准库 `zipfile` 打包。正文使用宋体（`eastAsia="SimSun"`），
标题加粗、条目缩进，A4 页面尺寸与 2 cm 页边距。表格暂不导出，避免结构错乱。

### 3.8 拒答阈值校准

阈值 4.0 由测试集校准：7 个应答问题的最低分为 5.9（图书馆能借几本书），4 个领域外
问题的最高分为 3.3（食堂几点开门）。取 4.0 使两类完全分开并保留约 1.3 倍余量。
阈值定义在 `learning_qa.MIN_SCORE`，且通过接口返回前端显示。

### 3.9 与 Module 2 的数据传递

学生在问答中成功提问时，`learning_qa.bump_activity()` 将当日 `risk_activity.qa_asks`
加 1。该记录是 Module 2 “智能问答次数”指标的唯一数据来源，两个模块因此在运行时
存在真实数据流。

## 4. Module 2：可解释的学业风险

### 4.1 技术选型

- 缺少真实标签：在合成数据上训练分类器，得到的是对合成分布的拟合，指标不具备
  解释力。
- 制度要求可解释：《学业预警管理办法》第 4 条要求向学生公开全部依据与计算口径，
  规则引擎天然满足。
- 样本量小：12 名学生、每人 15 条考核记录，不足以支撑统计学习。

报告中应表述为：本模块为规则引擎，阈值来自校规与教务经验；机器学习模型列为后续
工作，需两个学年的真实数据与伦理审批。

### 4.2 指标体系与公式

| 指标 | 权重 | 窗口 | 风险分量 |
|---|---|---|---|
| 作业按时提交 | 0.30 | 近 21 天 | `clamp((0.95 - r) / 0.55)`，r 为按时提交率 |
| 成绩趋势 | 0.30 | 已出分记录 | `max(clamp((B - A) / 20), clamp((60 - A) / 25))` |
| 平台登录次数 | 0.20 | 近 14 天 | `clamp((10 - n) / 10)` |
| 智能问答次数 | 0.20 | 近 14 天 | `clamp((3 - k) / 3)` |

```
score = 100 * sum(w_i * risk_i) / sum(w_i for available indicators)
```

`clamp` 限定在 [0, 1]。分母仅计入有数据的指标，因此某项缺数据时不会压低总分，
而是重新分配权重。该行为由“删除全部成绩记录”的测试覆盖。

### 4.3 等级与覆盖率

| 分数 | 等级 | 制度对应动作 |
|---|---|---|
| 60 及以上 | 高风险 | 学院组织干预、辅导与缓考评估 |
| 35 至 59 | 关注 | 导师面谈并制定学习改进计划 |
| 35 以下 | 正常 | 无需干预 |
| 覆盖率低于 40% | 数据不足 | 不输出等级，提示补充数据 |

阈值与办法第 3 条的三级预警（初级提示、中级关注、高级干预）对应。办法以“触发的
情形数量”分级，本实现将情形数量替换为连续分数后切分，边界经 12 个合成画像调校，
使“成绩良好但几乎不登录”的学生落入关注而非高风险，该行为由测试
`test_good_grades_low_activity_is_watch_not_high` 覆盖。

### 4.4 自动预警

风险分达到 `AUTO_ALERT_SCORE`（60）时触发，向学生与其学业导师各写入一条通知，
`kind = auto`，`author = system`。同一学生同一等级在 `ALERT_COOLDOWN_HOURS`（168 小时，每周一次）
内不重复发送，避免每次巡检产生重复消息。

触发时机：

1. 服务启动时执行一次巡检；
2. 每 `CAMPUSCARE_ALERT_INTERVAL` 秒由后台线程执行一次；
3. 教师点击“重新扫描”时立即执行。

三个入口都调用 `alert_if_needed()`，冷却判断集中在该函数内，因此不会重复。

教师留言使用同一张表，`kind = manual`，`author` 为教师账号，仅发给学生本人；
正文选填，留空时按主导因素与建议自动生成。

### 4.5 合成数据

固定随机种子 `20260216`，12 个画像：

| 画像 | 人数 | 特征 | 预期结果 |
|---|---|---|---|
| stable | 4 | 提交率 96%、均分 78、每日登录 | 正常（0 至 9 分） |
| watch | 4 | 提交率 72%、均分下滑 9 分 | 关注（35 至 50 分） |
| slip | 1 | 提交率 62%、均分下滑 13 分 | 关注与高风险边界（约 58 分） |
| high | 2 | 提交率 38%、均分 45、几乎不登录 | 高风险（80 分以上） |
| isolated | 1 | 成绩良好但几乎不登录 | 仅到关注（约 38 分） |

`isolated` 画像用于验证单一信号不产生高风险结论。

## 5. 角色模型与权限

五类用户彼此独立，通过 `users.identity` 区分，不合并为高权限账号。

| 身份 | 职责 | 明确不具备 |
|---|---|---|
| 学生 | 提问、查看本人风险与通知 | 查看其他学生、进入后台 |
| 教师 | 所带学生风险名单、依据、留言 | 进入知识库后台、修改账号 |
| 行政人员 | 场地与证明审批（其他子系统） | — |
| 维修人员 | 设施维修（其他子系统） | — |
| 系统管理员 | 知识库语料、系统日志、账号一览 | 查看学生成绩与风险、发送预警 |

教师与系统管理员分工不同：数据范围不同（教师按 `advisor` 过滤，系统管理员在风险
接口无数据返回）、职责不同（面向学生与面向系统资产）、审计不同（留言记录作者，
语料变更记录文件名与时间）。

接口权限矩阵：

| 接口 | 学生 | 教师 | 系统管理员 |
|---|---|---|---|
| `/api/qa/ask`、`/api/qa/feedback` | 是 | 是 | 否（无界面入口） |
| `/api/risk/me` | 是 | 否 | 否 |
| `/api/risk/overview`、`/student/<id>`、`/scan`、`/notify` | 否 | 是（仅所带学生） | 否 |
| `/api/qa/source/<doc_id>` | 是 | 是 | 否 |
| `/api/qa/knowledge`、`/gaps`、`/corpus`、`/rebuild` | 否 | 否 | 是 |
| `/api/admin/users`、`/api/admin/logs` | 否 | 否 | 是 |

## 6. 安全措施

| 措施 | 实现 |
|---|---|
| 密码存储 | PBKDF2-HMAC-SHA256，每用户独立随机盐，120k 次迭代 |
| 会话 | HttpOnly、SameSite=Strict 的 Cookie，12 小时过期 |
| CSRF | 每个会话一个令牌，所有写请求校验 `X-CSRF-Token` |
| 越权 | `_visible_students()` 限定数据范围；`_require_teacher()`、`_require_sysadmin()` 统一拦截 |
| 跨站请求 | 校验 `Origin` 与 `Host` 一致 |
| 静态资源 | 白名单映射，不做路径拼接 |
| 文件上传 | 文件名白名单正则、长度上限、必须包含 `##` 章节 |

## 8. 已知限制

1. 语料由项目组编写，检索效果仅在该语料上验证；更换语料需重新校准 `MIN_SCORE`。
2. 二元字检索不具备语义能力，同义改写依赖手工维护的同义词表，当前覆盖约 40 个
   高频说法。
3. 抽取式的句子选择为启发式规则（词项重叠与位置），复杂问题会出现照抄原文的
   情况，这是不生成内容所付出的代价。
4. 生成路径依赖本机 Ollama，未纳入自动化测试。
5. 指标共四项，未纳入出勤、门禁、借阅等其他信号；未做公平性分析。
6. 合成数据的分布由项目组设定，其上的指标不能作为算法有效性证据。
7. 后台巡检使用进程内线程，生产环境应改用外部调度。

## 9. 后续工作

- 检索：引入向量检索并与 BM25 组成混合检索，替换范围限于 `Index.search()`。
- 问答：接入本地模型后进行 30 题人工评测，标注正确、部分正确、错误、应拒答四类，
  报告准确率与拒答率。
- 风险：使用真实历史数据训练可解释模型（逻辑回归或决策树），与规则引擎做对比，
  指标采用 Precision@K。
- 公平性：按专业与年级分组检查分数分布，必要时调整阈值。
- 工程：接入单点登录；语料维护增加版本历史与回滚；账号管理接入后台管理模块后，
  将只读列表升级为可编辑。
