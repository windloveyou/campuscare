# CampusCare 学习支持子系统

GlobalConnect University（GCU）智慧校园项目中的学习支持子系统，包含 Module 1
智能问答助手与 Module 2 学业风险预警。设施维护、证明服务等其他子系统由小组成员
在各自的仓库中维护，不在本仓库范围内。

- 课程：CSIT883 System Analysis and Project Management
- 分支：`feature/module1-module2`
- 运行环境：Python 3.9 及以上，仅使用标准库

## 1. 范围

| 模块 | 职责 | 不在范围内 |
|---|---|---|
| Module 1 | 校级制度问答，附原文出处；证据不足时拒答；语料维护 | 开放式闲聊、查询个人成绩、语音输入 |
| Module 2 | 基于规则的学业风险评分、自动预警、教师留言 | 成绩预测、自动处分、考勤监控 |

子系统区分五类用户身份。本仓库涉及其中三类，另外两类属于其他子系统。

| 身份 | 在本子系统中的职责 |
|---|---|
| 学生 | 提问；查看本人风险画像与通知 |
| 教师 | 查看所带学生的风险名单与依据；向学生发送留言 |
| 行政人员 | 场地与证明审批（不在本仓库） |
| 维修人员 | 设施维修（不在本仓库） |
| 系统管理员 | 知识库语料维护、系统日志、账号一览 |

教师与系统管理员为两个独立账号。教师无法进入后台管理，系统管理员无法查看学生
成绩、风险分数与通知；两个方向的越权请求均由服务端返回 HTTP 403，并有自动化
测试覆盖。

## 2. 环境与安装

仅依赖 Python 标准库，`requirements.txt` 不包含第三方包。

```bash
git clone <repository-url>
cd campuscare-learning
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -B app.py
```

Windows 环境下解释器路径为 `.venv\Scripts\python.exe`。

服务默认监听 <http://127.0.0.1:8840>。首次启动会创建 `data/learning.sqlite3`，
导入 7 份语料，并按第 6 节说明生成合成学业数据。

### 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8840` | HTTP 端口 |
| `HOST` | `127.0.0.1` | 监听地址 |
| `CAMPUSCARE_LEARNING_DB` | `data/learning.sqlite3` | SQLite 文件路径 |
| `CAMPUSCARE_LEARNING_CORPUS` | `corpus/` | 知识库目录 |
| `CAMPUSCARE_OLLAMA_URL` | 空 | 设置后启用生成模式 |
| `CAMPUSCARE_MODEL` | `qwen2.5:7b` | 传给 Ollama 的模型名 |
| `CAMPUSCARE_ALERT_INTERVAL` | `3600` | 自动巡检间隔（秒，默认 1 小时） |

## 4. Module 1：智能问答

1. 知识库为 `corpus/` 下的 7 份 Markdown 文档，每份包含文档编号、责任部门、
   版本号与更新日期。
2. 文档按 `##` 章节切分为 51 个检索段落，每段 160 至 480 字，段落是引用单位。
3. 检索采用 BM25（k1 = 1.4，b = 0.65）。中文使用二元字切分并对单字赋较低权重，
   英文按整词切分；文档标题计 3 次、章节名计 2 次，起字段加权作用。
4. 同义词表把口语表述映射到制度用语，例如“挂科”映射为“不及格”，
   “晚交”映射为“延期”。
5. 最高相关度低于 4.0 时判定为知识库无依据，系统拒绝作答，列出最接近的章节，
   不作推测。
6. 两条回答路径共用同一检索结果：
   - 抽取式（默认）：从命中段落中选取句子并标注 `[n]`，不生成新内容；
   - 生成式：设置 `CAMPUSCARE_OLLAMA_URL` 后，命中段落作为唯一输入交给模型，
     要求逐句标注 `[n]`；调用失败自动退回抽取式，界面注明实际使用的方式。
7. 每次回答展示命中的文档、章节与相关度，正文中的编号与引用列表一致；超过 180 字的
   回答默认折叠，可展开查看全文。
8. 复杂问题会按文件分组取每份文件的最高段落，最多同时引用三份文件；单文件即可回答的
   问题只引用一个来源。
9. 每条回答附 2–3 个追问建议（本次未引用、但检索命中的其他章节），可一键追问；
   答案可复制。
10. 引用可查看原文，并可下载为 Word（`.docx`）文件，便于核对与打印。
11. 未作答与低置信度的问题按次数聚合，供系统管理员作为补充语料的依据。

### 语料维护

系统管理员可在后台上传 `.md` 文件。文件名须匹配 `[a-z0-9][a-z0-9_-]{1,39}\.md`，
正文须包含至少一个 `##` 章节且不超过 4 万字符。上传后立即重建索引，同名文件为覆盖。

## 5. Module 2：学业风险预警

### 5.1 评分模型

四项指标加权计算 0 至 100 的风险分。

| 指标 | 权重 | 统计窗口 | 判定规则 |
|---|---|---|---|
| 作业按时提交 | 0.30 | 近 21 天 | 按时提交率 95% 为基线，40% 记满分风险 |
| 成绩趋势 | 0.30 | 全部已出分考核 | 近三次均分较此前下降 20 分，或均分低于 60 |
| 平台登录次数 | 0.20 | 近 14 天 | 登录 10 次为基线，0 次记满分风险 |
| 智能问答次数 | 0.20 | 近 14 天 | 提问 3 次为基线 |

每项指标输出 [0, 1] 区间的风险分量：

```
score = 100 * sum(weight_i * risk_i) / sum(weight_i for available indicators)
```

指标记录不足时剔除该项并重新归一化剩余权重；可用权重低于 40% 时不输出等级，
标记为数据不足。

等级划分：60 分及以上为高风险，35 至 59 分为关注，35 分以下为正常。阈值依据
《学业进度与学业预警管理办法》第 2 条与第 3 条。

### 5.2 自动预警

学生风险分达到 `AUTO_ALERT_SCORE`（默认 60 分）时，系统分别向该学生与其学业导师
写入一条通知。同一学生同一等级在 `ALERT_COOLDOWN_HOURS`（默认 168 小时，即每周一次）内不重复发送。

巡检在服务启动时执行一次，此后每 `CAMPUSCARE_ALERT_INTERVAL` 秒由后台线程执行一次；
教师点击“重新扫描”时也会立即执行。

### 5.3 教师留言

教师可在学生依据面板中向学生发送留言。留言以 `kind = manual` 存储，出现在学生的
通知列表中，与系统自动预警分开标记。

### 5.4 合成数据

12 名学生由固定随机种子（`20260216`）生成，所有记录带 `synthetic = 1` 标记。画像
覆盖正常、关注、高风险，以及一名成绩良好但几乎不登录的学生，用于验证单一弱信号
不会产生高风险结论。

## 9. 已知限制

1. 语料由项目组为虚构学校编写，检索效果仅在该语料上验证；更换语料需重新校准
   拒答阈值。
2. 二元字检索不具备语义理解能力，同义改写依赖手工维护的同义词表。向量检索列为
   后续工作。
3. 生成路径依赖本机 Ollama 实例，未纳入自动化测试，仅测试了降级路径。
4. 学业记录为合成数据，在该数据上得到的任何指标都不能作为真实效果证据。
5. 未按专业或学生群体做公平性分析。
6. 后台巡检使用进程内线程实现，生产环境应改用独立的调度服务。
7. 账号创建、启用停用与角色分配属于后台管理模块，由其他成员负责；本仓库只提供
   只读的账号一览。
8. 界面样式与主系统 `web/style.css` 保持一致；合并时 `learning.css` 可整体并入，
   重名规则取值相同。
