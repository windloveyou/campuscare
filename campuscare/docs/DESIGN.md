# 设计与实施记录

## 设计目标

将校园设施的位置、身份、报修和维修历史串起来。优先实现可靠的角色工作流；规则与模型输出分别标识，保留模型接入点。原 proposal 的预测性维护在本版以合成事件上的独立实验实现，不误称真实故障预测。

## 架构

浏览器 HTML/CSS/JavaScript → 同源 HTTP API → SQLite。位置与房间通过台账匹配，不利用模型生成正式地点。照片在浏览器压缩为 JPEG；附件关联工单，下载时重新鉴权。

选择 Python 标准库服务以降低本地运行门槛。SQLite 保证单机演示持久化。不是生产级高并发服务；后续可迁移至团队统一后端。唯一必要第三方依赖 `qrcode` 用于标准二维码，不依赖外部生成网站。

## 业务实体

| 表 | 作用 |
|---|---|
| users | 三类角色，学生/老师身份、所属宿舍、维修技能 |
| sessions | 随机会话、到期时间、CSRF token |
| locations | 示意图坐标和校园区域，不是经纬度 |
| assets | 设施唯一编号、类别、区域、房间、最后确认时间 |
| tickets | 工单、报修人、维修人员、状态、优先级、结果、并发版本 |
| events | 状态与说明变更的追加记录 |
| attachments | 经校验的 PNG/JPEG 内容及关联工单 |
| followers | 用户确认重复后关注的工单 |
| inspections | 管理员创建的巡检及核查结果 |

## 角色约束

- 普通用户可以报修公共设施和本人宿舍设施；查看自己的或已关注的工单。
- 维修人员查看自己被分配的工单，只有该人员可执行维修状态变更。
- 管理人员派单、改派、验收、查看统计、创建和确认巡检。
- 后端对每个入口鉴权，前端隐藏按钮不作为安全控制。
- 重复候选只在有权查看的设施内返回摘要，关注后可查看该公共问题详情。其他宿舍设施无法被查询或关注。

## 状态流

`pending → assigned → in_progress → review → closed`

`in_progress → waiting_parts → in_progress`

`review / closed → pending`（重新打开，清除旧分配）

`pending → cancelled`

管理人员可对待确认、已派单、维修中、等配件的工单重新指派。变更必须携带当前 `version`，旧版本返回 409，防止两个人互相覆盖。更新及审计日志在同一数据库事务提交。

资产状态由所有未关闭工单按需维修状态派生；没有活动工单时，具有确认记录才显示“记录正常”。正常不代表传感器实时检测。新报修先标记待确认，并非已证实物理故障。

## API

| 方法 | 路径 | 功能 |
|---|---|---|
| POST | /api/login | 演示账号登录 |
| POST | /api/logout | 当前会话失效 |
| GET | /api/bootstrap | 按角色过滤的校园、设施、工单、巡检、连接状态 |
| POST | /api/analyze | 规则辅助或配置后的 Ollama 图文分析 |
| POST | /api/tickets | 创建报修与照片附件 |
| GET | /api/tickets/:id | 有权限的工单及事件记录 |
| POST | /api/transition | version + action + note 的状态操作 |
| POST | /api/follow | 确认同一设施的重复问题，关注原工单 |
| POST | /api/assets | 管理员登记新设施，初始为待核实 |
| POST | /api/assets/update | 管理员修改名称、位置补充及停用状态 |
| GET | /api/attachments/:id | 重新鉴权的图片读取 |
| GET | /api/qr?asset=:id | 设备报修链接二维码 |
| POST | /api/ask | 管理员的三类受控数据库统计 |
| GET | /api/forecast | 合成预测实验指标与设备记录评分 |
| POST | /api/inspections | 从维护列表创建巡检 |
| POST | /api/inspections/complete | 保存核查结果 |

写请求要求会话和 `X-CSRF-Token`，登录除外；浏览器 Origin 与 Host 必须一致。

## 预测实验

目标是模拟下一观察窗口是否出现新的报告事件，不能把报告事件直接解释为经过确认的物理故障。

- 生成 800 台训练设备、300 台独立测试设备，固定随机种子 883/2026。
- 每台设备独立生成 134 天事件。特征只读取第 120 天及之前的数据；标签是第 121–134 天是否出现事件。
- 特征：近7/30/90天次数、距上次事件天数、短间隔复发次数。
- 训练集拟合标准化参数与 L2 正则逻辑回归；测试集仅用于报告指标。
- 基线：按近30天报修次数排序。报告 AUROC 与 Brier 分数。
- 当前资产列表使用相同特征提取，但属于模拟数据上的演示性评分。少于3条历史不输出分数；有分数也不称实测故障概率。
- 巡检由管理员显式创建，不根据模型自动停用或生成确定故障。
