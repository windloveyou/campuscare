# 开通真实邮件验证码

用户填写注册邮箱，点击“获取验证码”，然后去该邮箱的收件箱查看 CampusCare 邮件，将其中6位验证码填回页面。找回密码必须使用已经验证的注册邮箱。验证码10分钟有效、仅能用一次，重发间隔60秒。

## 管理员只需配置一个发件邮箱

1. 在运行 CampusCare 的电脑上打开 http://127.0.0.1:8830，以管理员登录（本地演示账号 `admin`，密码 `Campus2026!`）。
2. 点击顶部“邮件服务”，选择 QQ、163 或 Gmail，填写发件邮箱。
3. 在邮箱服务商网站生成授权码/应用专用密码，将其填入本机页面。不要使用普通登录密码，也不要将授权码发到聊天、截图或提交源码。
4. 点击“保存并启用邮件发送”。配置立即生效，无需重启。
5. 填写测试收件邮箱，点击“发送测试邮件”，到邮箱确认收件。可以分别测试 Gmail、QQ、163。服务器接受邮件并不等于收件箱已经收到。
6. 退出管理员账号，进入注册或找回密码页面获取验证码。真实邮件模式不会在页面显示验证码。

发件人可以是 QQ，收件人可以是 Gmail 或163；不需要为每类收件邮箱各配置一个发件账号。普通收件用户无需配置 SMTP。

| 发件服务 | 自动填写的服务器 | 加密端口 | 需要准备 |
|---|---|---|---|
| QQ（含 foxmail.com 地址） | smtp.qq.com | 465 / SSL | 开启 SMTP 后生成的授权码 |
| 163 | smtp.163.com | 465 / SSL | 开启 SMTP 后生成的客户端授权密码 |
| Gmail | smtp.gmail.com | 465 / SSL | 开启两步验证后生成的应用专用密码 |

## 从哪里获取授权码

- **QQ：** 登录 [QQ 邮箱](https://mail.qq.com)，在设置中找到 POP3/IMAP/SMTP 服务，开启 SMTP 并按提示完成身份验证、生成授权码。页面名称可能随邮箱版本变化。
- **163：** 登录 [163 邮箱](https://mail.163.com)，设置 → POP3/SMTP/IMAP，开启 IMAP/SMTP 或 POP3/SMTP 服务，按提示获取客户端授权码。可参考 [华为官方客户端配置说明](https://consumer.huawei.com/cn/support/content/zh-cn15872099/)。
- **Gmail：** 开启两步验证，再进入 [Google 应用密码](https://myaccount.google.com/apppasswords) 为 CampusCare 创建密码。输入带空格的应用密码时系统会去除分组空格。部分学校/企业或高级保护账号不提供此功能，可改用 QQ/163 发件；这不影响 Gmail 用户收件。见 [Google 官方说明](https://support.google.com/accounts/answer/185833?hl=en)。

运行服务的电脑必须能够连接所选邮箱的 SMTP 服务器；选 Gmail 发件时尤其要确认当前网络可连接 Google。服务运行在本机，因此关闭服务后就不能发验证码。

## 故障提示

| 页面提示 / 现象 | 处理方式 |
|---|---|
| 认证失败 | 确认发件地址正确、已开启 SMTP、使用授权码而非登录密码；授权码被撤销后需重新生成 |
| 无法连接 / 加密失败 | 检查网络、SMTP访问限制、系统时间；不支持关闭证书校验或明文发信 |
| 收件邮箱被拒绝 | 检查地址是否存在、邮箱容量、收件规则 |
| 邮件服务拒绝发信 | 查看发件服务商的安全提醒、发送额度、风控或退信提示 |
| 服务器接受但未收件 | 等待片刻，检查垃圾邮件、过滤规则和退信；需要分别实测不同收件邮箱 |
| 注册页仍显示演示模式 | 保存配置后重新进入注册页；确认使用同一个服务进程与数据目录 |
| 找回密码未收到 | 确认使用已注册并验证的邮箱；接口统一提示，避免泄露账号是否存在 |

## 配置与验证范围

配置只允许在本机以管理员身份修改；文件默认是 `data/mail-settings.json`，权限0600，仅当前系统用户可读写。授权码为了 SMTP 登录必须可被服务读取，因此不作不可逆哈希；用户登录密码、验证码仍分别保存加盐哈希。接口不返回授权码，也不将 SMTP 原始错误回传浏览器。备份运行目录时应把该文件视作私密凭据。

没有页面配置时可使用环境变量（见 README）。页面保存的配置优先，停用服务会删除文件内的授权码并保持停用。配置损坏时停止发信，不会回退到演示验证码。

自动化已覆盖 SMTP 消息构造、三类收件域名、注册/重置闭环、权限、CSRF、失败处理和浏览器页面。SMTP 传输在这些测试中为模拟实现；真正跨服务商送达必须由管理员配置自己的发件凭据并通过测试收件确认。本项目未提供发件账号、代购服务或短信验证码。
